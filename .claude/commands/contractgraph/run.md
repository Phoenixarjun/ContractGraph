---
description: Execute a compiled workflow graph against a runtime input — run ready nodes per the graph, validate/verify each output, retry only failures, aggregate accepted sections, run global verification, and write final artifacts under a unique run directory.
argument-hint: contracts/<bundle> --input "<value>" [--roles a,b] [--resume-refs ...] [--job-urls ...] [--as-of YYYY-MM-DD] [--force-refresh] [--dry-run]
allowed-tools: Read, Write, Glob, Grep, Bash, Task
---

Requires a prior successful `/contractgraph:init`. If `runtime/compiled/graph.json` is missing or `runtime/compiled/compilation-report.md` shows the last compilation failed, stop and tell the user to run `/contractgraph:init` first.

Arguments from the user: $ARGUMENTS

Parse: the bundle path (default `contracts/company-research`); `--input` (required runtime value — for company-research this is the company name); optional `--roles`, `--resume-refs`, `--job-urls`, `--as-of`, `--force-refresh`, `--dry-run`, `--time-bounded`, `--token-efficient`.

**Concurrency is weighted per class, not one flat cap** (from `policies.json.execution.concurrency.modes`). Every ready node is classified `heavyResearch` (has WebSearch/WebFetch) or `lightSynthesis` (Read/Write only); the reusable `section-verifier`/`global-verifier` subagents classify as `verifier`/`globalVerifier`. Compute admission with `python scripts/schedule_plan.py --bundle <bundle> --compiled runtime/compiled --mode <mode> --ready <ready-node-ids.json>` — it admits up to each class's cap for the active mode and defers the rest (never silently drops them). `heavyResearch` stays **≤2 in every mode** by policy, including `--time-bounded`: time-bounded only raises `lightSynthesis`/`verifier` throughput, never the research-burst size, to avoid unsafe concurrent web-research spikes. `--token-efficient` lowers every class's cap and reuses agents to process nodes in batches. The legacy `policies.json.execution.concurrencyModes` integer is kept only as a backward-compatible aggregate ceiling — the per-class caps in `concurrency.modes` are authoritative.

## Dry run
If `--dry-run` is present, run `python scripts/dry_run.py --bundle <bundle> --compiled runtime/compiled --input <input.json>` and present its plan: selected graph + layer order, parallel groups, chosen models, loaded context references, selected skills, expected cache hits, estimated budget, and the files that would be written. **Write nothing else and stop.**

## Full run — the lifecycle
1. **Verify init is current.** Recompute context/contract/policy/skill/agent hashes and compare to the compiled manifests; if anything changed (or `--force-refresh`), tell the user to re-run `/contractgraph:init` (do not silently recompile here).
2. **Create the run dir** `runtime/runs/<run-id>/` with subdirs `manifests/ node-state/ evidence/ summaries/ sections/ verification/ telemetry/raw/ logs/ final/`. Write `run.json` (runId, bundleId, startedAt, input summary) and `input.json`. Snapshot the compiled graph to `graph.snapshot.yaml` and copy the compiled manifests (including `node-packets/`) into `manifests/`.
3. **Resolve runtime input** against `runtimeInputs`: required fields present (ask if missing); optional fall back to bundle defaults (e.g. `targetRoles`).
4. **Compute a cache key per node** with `python scripts/cache_key.py --bundle <bundle> --node <id> --input <input.json> --dep-summaries <summaries-hash-map.json> --node-packet runtime/compiled/node-packets/<id>/packet.json`. The `--dep-summaries` map folds in each upstream dependency's current `summaryHash` (from `summaries/<depNode>.summary.json`) so an unchanged upstream output keeps the key stable and a real change busts it. A node with a valid, fresh cache entry becomes `SKIPPED_CACHE` (unless `--force-refresh`). Never cache invalid/partial/unverified/stale outputs.
5. **Walk the graph by layer.** A node is `READY` only when every `dependsOn` node is `ACCEPTED` or `SKIPPED_CACHE`. Admit ready nodes per the weighted concurrency caps above (`schedule_plan.py`), never a single flat count. Each producer loads **only its compiled `runtime/compiled/node-packets/<id>/packet.json`** — its own contract, its declared `contextRefs` (load the referenced canonical file only when `loadWhen` is `full-if-exact-evidence-required`; otherwise a summary is enough), its `dependencySummaryRefs` (resolved against `summaries/<depNode>.summary.json`, never the dependency's full section), and its `evidenceRegistryRef` — never the whole bundle, never all canonical context, never an upstream node's full output. Isolate node responsibilities — never assign one agent per tiny field; a node agent owns its whole subcontract. `resume-analysis` is a map node — run it once per configured role, writing `sections/resume-analysis/<roleId>.json`.
6. **Dispatch each node to its generated subagent** (`.claude/agents/generated/<id>`). Record state transitions in `node-state/<id>.json` (PENDING→READY→RUNNING→…). A worker may complete its own node only; it must never approve its own output or declare the whole workflow complete. Node output cites evidence as `evidence: [{ref, claims}]` against the run's shared registry — never an embedded `sources[]` array of full metadata (see step 8).
7. **Structural validation** of each raw output: `python scripts/validate_node_output.py sections/<id>.json --bundle <bundle> --node <id>`. Invalid JSON/shape → `STRUCTURAL_FAILED` → one bounded structural-repair attempt (haiku) → re-validate.
8. **Evidence registration + reference/URL checks.** Fold any newly cited sources into the run's shared registry: `python scripts/source_registry.py --registry runtime/runs/<run-id>/evidence/source-registry.json --sources <node-sources.json> --out-refmap <refmap.json>` — dedups by normalized URL, so the same real-world source always gets the same `SRC_` id no matter which node cites it first, and remap the node's `evidence[].ref` values via the returned refmap before validating. Then `python scripts/validate_references.py sections/<id>.json --bundle <bundle> --evidence-registry runtime/runs/<run-id>/evidence/source-registry.json` (evidenceRefs/contextRefs/roleIds resolve against the EXTERNAL registry, since a section no longer embeds full source metadata) and, when policy requires reachable URLs, `validate_source_urls.py` (prefer Claude Code WebFetch for live reachability).
9. **Independent semantic verification** by a *different* subagent than the producer (`section-verifier`), using the reusable verifier skills. It returns exactly the shape in `scripts/schemas/verifier-verdict.schema.json`: `{nodeId, verifier, status, issues:[{path, issueType, claim?, repairInstruction}], conflicts, confidence}` — it names repair targets by JSON path, it never rewrites or reproduces the node's content (the schema's `additionalProperties:false` rejects any `content`/`section`/`rewrite` field a verifier might try to add). Map failures to `SEMANTIC_FAILED` / `EVIDENCE_FAILED` / `FRESHNESS_FAILED`.
10. **Targeted repair, this node only,** up to `policies.execution.maxRetriesPerNode`: semantic → targeted repair; evidence → source repair (not full regeneration); freshness → refresh only stale claims. Every retry increments attempt metadata. A required node that exhausts retries becomes `EXHAUSTED` and blocks final completion.
11. **Accept** a node (`ACCEPTED`) only when structural + semantic + evidence + freshness all pass. Its `sections/<id>.json` is now immutable for this run. Immediately build its handoff summary: `python scripts/build_dependency_summary.py --bundle <bundle> --node <id> --section sections/<id>.json --out runtime/runs/<run-id>/summaries/<id>.summary.json` — downstream nodes read this compact `{handoff, evidenceRefs, confidence}` summary, never the full section.
12. On refresh of a previously-cached node, run `python scripts/preserve_user_state.py` so user-owned tracking fields are never overwritten by research.
13. **Deterministic aggregation** once all required nodes are terminal-OK: `python scripts/merge_verified_sections.py --bundle <bundle> --sections runtime/runs/<run-id>/sections --out runtime/runs/<run-id>/final/final.json --run-meta <run-meta.json> --evidence-registry runtime/runs/<run-id>/evidence/source-registry.json` (merges only accepted sections; resolves each section's `evidence[].ref` against the run registry, and any legacy embedded `sources[]`, into one deduplicated global `sourceRegistry`; rejects duplicate ownership).
14. **Validate the final artifact:** `python scripts/validate_final_output.py final/final.json --bundle <bundle>` and `validate_references.py` on the final.
15. **Global verification (Opus)** via the `global-verifier` agent against `contract.bundle.json.globalValidation[]` and the main contract. Pass compact evidence/conflict summaries, not raw full-node dumps. On failure, route repair to the implicated node(s) only — do not restart the run.
16. **Write final artifacts** to `final/`: `final.json`, `report.md`, `trace.json` (`python scripts/generate_trace.py --run runtime/runs/<run-id>`), `cost.json` (`python scripts/telemetry_normalize.py --run runtime/runs/<run-id> [--claude-code <export>] [--opencode <export>] [--local telemetry/raw] --out final/cost.json` — normalizes whatever usage telemetry the active runtime actually exposes into per-request/per-node/per-model/per-purpose/per-attempt aggregates; a metric the runtime doesn't expose is written `null` and marked `false` in `available`, never fabricated), `validation-report.json`.
17. **Optional TOON transport, benchmark-config-gated only.** If (and only if) the active run config sets `toon: "selective"` (never in normal/default execution), sections may encode the arrays listed in `policies.json.tokenEfficiency.toon.eligibleArrays` as TOON instead of JSON for the wire/storage transport, per the measured decision in `runtime/compiled/<bundle>/toon-benchmark.json`. The node's OWN validated output (what `validate_node_output.py` checks) is still canonical JSON — TOON is a transport encoding around it, applied via `scripts/toon_codec.py` with `enable_toon=True`, never a schema change.
18. **Derived context** — only from verified outputs — to `final/derived-context.json` (and, if the user opts in, `context/derived/`) with originating runId, node, source contract version, contextRefs, evidenceRefs, confidence, creation date, freshness date, privacy classification. Never overwrite canonical; never convert research into user-owned truth.

Report which nodes ran, which were cached, which retried, and the final verification verdict. If any required node is `EXHAUSTED` or global verification fails after retries, report the run **incomplete** with the specific node(s) and reason — never report completion. Private outputs stay under `runtime/runs/` (git-ignored); never write them into public example directories.
